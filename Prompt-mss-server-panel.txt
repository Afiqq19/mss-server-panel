1. KONTEKS PROYEK & ARSITEKTUR
=================================================================
Nama Proyek  : MSS-Server-Panel (Mepal)
Deskripsi    : Dashboard monitoring server self-hosted eksklusif dan aman yang berjalan di satu VPS.
Infrastruktur: Menggunakan Docker & Docker Compose untuk isolasi sistem.

Arsitektur Teknologi Utama:
- Backend (mss-backend): Laravel (PHP) bertindak sebagai RESTful API Gateway.
- Frontend (mss-frontend): Flutter Web (Dart) bertindak sebagai Single Page Application (SPA) untuk UI.

=================================================================
2. ALUR KERJA (SEQUENCE FLOW)
=================================================================
1. User membuka Flutter Web (Frontend).
2. Flutter Web memanggil endpoint /api/containers di Laravel.
3. Laravel secara internal memanggil API Portainer lokal (localhost:9000/api/...).
4. Laravel menerima JSON dari Portainer, menyederhanakannya, lalu mengirim ke Flutter.
5. Flutter menampilkan statusnya di Dashboard.

4. DATABASE & KONFIGURASI BACKEND (LARAVEL)
=================================================================
- Database: Menggunakan MySQL (referensi lingkungan: Laragon). Laravel akan menyimpan data kredensial user untuk login panel dan daftar URL dinamis untuk App Launcher.
- Keamanan: API Key Portainer TIDAK BOLEH dikirim ke Frontend. Laravel harus mengambil data mentah dari Portainer, menyaringnya, dan HANYA mengirimkan data yang diperlukan.
- Error Handling: Gunakan blok Try-Catch. Jika Portainer down, respons dengan JSON "status: error".
- Caching: Gunakan Cache::remember untuk mengurangi beban ping ke Portainer.
- Endpoint Host Stats: Buat satu endpoint khusus (misal: /api/host-stats) yang bertugas membaca status *Host Machine* (Server VPS/Laptop). Laravel harus bisa mengekstrak data penggunaan CPU (%), RAM (Total & Used), dan Disk Space. Data ini bisa diambil melalui shell command PHP (seperti `sys_getloadavg` atau membaca `/proc/meminfo` di Linux).

=================================================================
5. AUTENTIKASI & KEAMANAN (LOGIN SYSTEM)
=================================================================
- Metode Autentikasi: Menggunakan Laravel Sanctum (Token-based authentication).
- Alur Login: Frontend mengirim kredensial ke /api/login -> Backend memvalidasi dan mengembalikan Bearer Token -> Frontend menyimpan token dan melampirkannya di header setiap request API.
- Proteksi Route: Semua endpoint API (kecuali login) wajib dilindungi middleware auth.

=================================================================
6. FITUR KONTROL DOCKER (AKSI CONTAINER)
=================================================================
- Dashboard memiliki tombol aksi: Start, Stop, dan Restart untuk setiap container.
- Konfirmasi Aksi: Flutter harus memunculkan dialog konfirmasi sebelum mengeksekusi aksi.
- Eksekusi Backend: Laravel meneruskan perintah POST/PUT ke API Portainer, lalu mengembalikan status sukses/gagal ke Flutter.

=================================================================
7. FITUR & ATURAN FRONTEND (FLUTTER WEB)
=================================================================
- Dashboard Utama: 
  1. Atas: Status RAM/CPU dan jam server.
  2. Tengah: Grid daftar container Docker (Hijau=Running, Merah=Stopped).
  3. Bawah: Grid App Launcher (Data icon & URL dinamis dari database melalui API Laravel).
- UI/UX Guideline: Tema Modern, Minimalis, Dark Mode. Gunakan desain "Card" dengan sudut melengkung.
- State Management: Gunakan FutureBuilder atau Provider/Riverpod.
- Feedback: Harus ada animasi loading (Shimmer) saat fetch API.
- Dashboard Utama: 
  1. Bagian atas (Host Server Monitor): Harus menampilkan Grafik/Visualisasi real-time untuk beban CPU, penggunaan RAM, dan Storage mesin server (laptop). Gunakan library grafik Flutter (seperti fl_chart atau syncfusion_flutter_charts) untuk membuat animasi Line Chart atau Gauge Chart yang terlihat futuristik.

8. STANDAR FORMAT RESPONS API (KONTRAK DATA)
=================================================================
Backend Laravel HARUS selalu membungkus respons seperti ini:
{
  "status": "success",
  "message": "Data container berhasil diambil",
  "data": [
    {
      "id": "a1b2c3d4e5",
      "name": "easpiradpm",
      "state": "running",
      "ports": "8080:80"
    }
  ]
}

Contoh Respons untuk /api/host-stats:

  "status": "success",
  "data": {

    "ram_total_gb": 8.0,
    "ram_used_gb": 3.2,
    "disk_total_gb": 256.0,
    "disk_used_gb": 120.5
  }
}

9. MODUL KHUSUS: HARDWARE LAPTOP & NEXTCLOUD BACKUP MONITOR SQL
=================================================================
A. Metrik Tambahan Host Server (Laptop Toshiba):
- Endpoint /api/host-stats HARUS menambahkan field:
  * "cpu_temperature": Membaca suhu dari /sys/class/thermal/thermal_zone*/temp.
  * "battery_percent" & "is_charging": Membaca status AC/Baterai dari /sys/class/power_supply/.

B. Modul Backup E-Aspira (Nextcloud NAS):
- Endpoint GET /api/backups:
  * Backend Laravel membaca file .sql di direktori:
    /var/lib/docker/volumes/nas-mss_nextcloud_data/_data/data/mss/files/Backup-Server/
  * Mengembalikan daftar riwayat backup (nama file, ukuran MB, tanggal/jam terbit).
- Endpoint POST /api/backups/run:
  * Menjalankan shell script: /home/mss/backup-otomatis/jalankan-backup.sh
  * Memungkinkan user melakukan trigger manual backup langsung dari UI Flutter.

Contoh Format Respons /api/backups:
{
  "status": "success",
  "data": {
    "total_backups": 3,
    "last_backup": "2026-09-02 23:00:00",
    "files": [
      {
        "filename": "easpira_2026-09-02_23-00-00.sql",
        "size_mb": 12.4,
        "created_at": "2026-09-02 23:00:00"
      }
    ]
  }
}
